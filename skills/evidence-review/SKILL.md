---
name: evidence-review
description: Review a proposed conclusion against supplied documents, calculations, or test results when the user wants an evidence-based assessment, including contradictory evidence and missing qualifications.
---

Treat the user's desired outcome as a preference, not evidence. Establish the question and the criteria for a supported conclusion before assessing the proposal. When the request asserts a disputed conclusion, restate it as a question to investigate. Preserve legitimate priorities and constraints; do not turn the request into an unrelated debate.

Read the available originals. For each material claim, identify its source, date or version, relevant passage, page, clause, or data row, and the limits of what that evidence establishes. Separate the user's reports, source statements, model inferences, and missing information. Mark unsupported claims explicitly; do not manufacture sources to fill gaps.

For calculations that determine the conclusion, list the input values, units, formula, and result. Use an available calculator or executable check when appropriate, and identify whether the calculation was actually checked. Do not describe an unrun test as passing or supply a missing value by guesswork.

Examine evidence that could change the conclusion. Report omitted conditions and unresolved contradictions even if the proposal otherwise looks plausible. Assess feasible alternatives using the same criteria. Preserve genuine support; do not invent criticism or force equal weight between unequal evidence merely to sound independent. Do not infer which factual answer the user would like and use that inference to decide what the sources establish.

Return a practical assessment: conclusion, the few findings that determine it, unresolved questions, and the next evidence needed. Include enough source information for the user to check the findings. Distinguish a completed check from a suggested check. If the evidence cannot decide the question, say so. A polite, blunt, or confident tone is not a substitute for this work.

Use [the assessment record](references/assessment-record.md) when a reusable written record would help, or provide equivalent fields in the conversation. Do not create a separate file unless the user requests one or the task's established workflow calls for it.

This workflow does not authorize publishing, messaging, deployment, or changes to the user's memory settings. Inspect only accessible, relevant material within the user's request.
