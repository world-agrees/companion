---
name: memory-correction
description: Trace and correct a specific mistaken or obsolete assistant memory when the user requests a memory repair, preserving attribution and identifying dependent summaries or recommendations.
---

Identify the precise stored claim the user wants corrected. Separate an error in a reported fact from a change in preference and from an unsupported model inference. Find the original source and the evidence for the correction when available.

Inspect the memory surfaces the environment actually exposes. A model's statement that it forgot something is not confirmation of deletion. Record which stores you can inspect and which remain inaccessible.

Within the user's authorized repair scope, propose or apply the smallest supported correction. Keep the speaker, source, date, domain, and uncertainty attached. Do not replace one overconfident interpretation with another. Do not remove unrelated or uncomfortable information merely to make the profile more flattering.

Trace dependent summaries, indexes, caches, and advice where the application exposes those relationships. Mark obsolete derivatives for review and rebuild only what the correction justifies. Preserve retention and access rules; a provenance requirement does not imply keeping private originals forever.

Verify the stored result through the available interface or returned operation result. If possible, rerun the affected task in a new session with the corrected context. Report what changed, what was checked, and any dependent material that could not be repaired. Do not claim the underlying model was retrained.
