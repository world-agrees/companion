# Friday review, Monday preparation

Choose one purpose: work, a named project, or a personal topic. The review works with the material the tool exposes or you supply. It is a proposed routine; nothing here schedules an automation or grants permission to delete history.

## Friday: review the week

Open the product's memory controls and the project's instructions and files yourself. Supply the relevant entries or summaries, their locations, and any dated evidence needed to check them. Avoid exporting an entire confidential workspace merely to make the prompt more complete.

```text
Review period: [dates]
Purpose: [one bounded project or personal context]
Material: [visible memory entries, relevant chats or local
history, project instructions, and dated source documents]

Help me curate the context for next week. Inventory only what
you can actually inspect and name unavailable stores.
For each candidate memory, distinguish a stated preference,
a dated report, a document-supported fact, and an interpretation.
Find obsolete information, unsupported generalizations,
conclusions from temporary frustration, and material from a
different purpose. Keep valid evidence even if uncomfortable.

Propose keep, correct, remove from active context, or investigate,
with the saved location, source, date, reason, and replacement
wording where supported. Identify earlier advice or summaries
you can actually inspect that depend on a mistaken claim.

Prepare a short next-week context brief for my review. Keep
unresolved claims labeled. Do not change settings, delete chats,
purge history, or edit saved files. Separate proposed changes
from anything already verified. Do not claim hidden memory is
visible, deletion is complete, or the underlying model changed.
```

Use [the review template](../templates/weekly-context-review.md) to record what you actually changed through the product controls. A new message accepting a correction is not proof that every stored summary changed.

## Monday: check what belongs in this task

Start in the project or mode appropriate to the purpose. Supply the reviewed brief and the current evidence, then paste:

```text
Task: [this week's decision or work]
Reviewed brief: [dated document]
Current sources: [identifiers, versions, and locations]

Before starting, identify which supplied facts and preferences
are relevant. List other personal context or previous conclusions
that are actually visible to you and could influence this task.
Flag unrelated, obsolete, disputed, or inaccessible material.
Do not turn an old interpretation into an established fact.
Ask for missing evidence that could change the result.
Tell me what available controls or changes I need to make if
irrelevant context remains; do not claim a prompt disabled it.
```

If a Wednesday conversation recorded “my manager is sabotaging this project,” Friday's goal is to check the source and qualify the claim. It is not to erase every criticism of the manager or the user's own mistakes. On Monday, an old unsupported judgment should not silently become the premise for deciding whom to invite to a planning meeting.

## Use the same workflow as a skill or a pasted prompt

The portable [weekly-context-review skill](../skills/weekly-context-review/SKILL.md) and [evidence-review skill](../skills/evidence-review/SKILL.md) package these procedures for compatible agents. A pasted skill's frontmatter does not install a memory control or grant extra source access.
